API LLM Privacy Proxy — Architecture

Proxy OpenAI-compatible avec filtrage PII en temps réel via un modèle de classification tokenique

Flux de données

  • • 1 — Client envoie une requête OpenAI-compatible
  • • 2 — Authentification Bearer Token vérifiée
  • • 3 — PII détectées via NLP sur l'entrée
  • • 4 — Model ID suffixé (ex: gpt-4o → gpt-4o-anonym)
  • • 5 — Requête envoyée à l'upstream
  • • 6 — Réponse filtrée (si FILTER_OUTPUT=true)
  • • 7 — Model ID re-suffixé avant retour client

Composants clés

  • • FastAPI : Framework web principal
  • • httpx.AsyncClient : Client HTTP asynchrone
  • • transformers : Pipeline HuggingFace NLP
  • • openai/privacy-filter : Modèle PII token-classification
  • • torch : PyTorch (CPU/CUDA/FP16/BF16)
  • • uvicorn : Serveur ASGI

Configuration

  • • UPSTREAM_BASE_URL : Backend LLM
  • • INBOUND_API_KEYS : Tokens d'authentification
  • • PRIVACY_MODEL_ID : Modèle de filtrage
  • • DEVICE : auto | cuda | cpu
  • • FILTER_OUTPUT : true | false
  • • MODEL_IDLE_UNLOAD_SECONDS : 300s par défaut

Observabilité

  • • GET /metrics : Métriques Prometheus
  • • GET /health : Health check complet
  • • x-privacy-filtered-tokens : Headers de réponse
  • • x-privacy-filtered-spans : Tokens filtrés
  • • x-privacy-filter-latency-ms : Latence filtrage

Redaction PII

  • • Placeholder stable : même span → même placeholder
  • • [PRIVATE_EMAIL_1], [PRIVATE_PERSON_1]...
  • • Filtre récursif dans JSON (profondeur illimitée)
  • • Clés JSON skip : model, role, type, stream...
  • • MERGE des spans qui se chevauchent

Optimisation GPU

  • • Chargement différé du modèle (lazy load)
  • • Unload automatique après N secondes d'inactivité
  • • torch.cuda.empty_cache() + gc.collect()
  • • MODEL_IDLE_UNLOAD_SECONDS=300 par défaut
  • • MODEL_IDLE_UNLOAD_SECONDS=0 pour désactiver
